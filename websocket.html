🔌 1. WS PROXY (proxy.py, sem TLS)
Disfarça o tráfego SSH como uma conexão web comum (handshake HTTP), sem criptografia própria — mais leve, mas visível em texto claro pra quem inspecionar o tráfego. Padrão automático na instalação/reinício do servidor: porta 80. Escolha outra porta abaixo pra trocar quando quiser — se a porta escolhida já tiver algum dos outros 3 modos ativo nela, ele é parado automaticamente pra liberar o lugar.
🔒 2. WSS TLS (TLS real)
Handshake WebSocket (RFC6455) de verdade, com TLS real por cima (certificado gerado na instalação) — o tráfego fica ilegível pra quem inspecionar a rede. Padrão automático na instalação/reinício do servidor: porta 8443.
🔐 3. WSS SSH (sem TLS)
Camuflagem "HTTP/1.1 101 SECURITY" confirmada por captura de rede real — sem TLS por cima. Padrão automático na instalação/reinício do servidor: porta 8888. Porta e destino (pra onde o tráfego é entregue depois de descamuflado) são livres pra trocar abaixo.
🛡️ 4. STUNNEL SSL (SSH sobre TLS "cru")
Encapsula o SSH direto num túnel TLS separado (sem a camuflagem HTTP dos modos WSS TLS/WSS SSH acima) — útil quando o cliente só precisa de uma porta puramente TLS. Padrão automático na instalação: porta 2053 → 127.0.0.1:22.
📡 5. NETSIMON-BHTTP
Servidor BHTTP embutido no painel — o binário já vem dentro do próprio projeto, nada é baixado de repositório externo na instalação nem na ativação. Fica instalado mas desligado por padrão; ative quando quiser pelas portas abaixo. Ativar aqui libera automaticamente as portas escolhidas dos outros modos (WS Proxy / WSS / WSS SSH / Xray) que estiverem ocupando-as.
